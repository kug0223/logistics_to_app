## 개요

### 현재 상황
- ✅ **단기 알바**: 날짜별 TO 생성, 그룹화, 지원 마감 N시간 전 설정 완료
- ❌ **장기 근무 (1개월 이상)**: 미구현 상태

### 핵심 차이점

| 구분 | 단기 알바 | 장기 근무 |
|------|----------|----------|
| TO 개수 | 날짜별 여러 개 | 1개만 |
| 지원 방식 | 날짜별 개별 지원 | 1번 지원으로 전체 기간 |
| 근무 형태 | 선택한 날짜만 | 전체 기간 통으로 |
| 마감 설정 | 각 날짜별 N시간 전 | 특정 날짜+시간 고정 |

## 장기 공고 생성 방식

### TO 구조 비교

#### 단기 알바 TO
```javascript
{
  jobType: "short",
  date: Timestamp(2025-03-15),  // 단일 날짜
  startDate: null,
  endDate: null,
  workDays: null,
  
  // 그룹 기능
  groupId: "group_001",
  groupName: "3월 파트타임 모음",
  isGroupMaster: true,
  
  // 마감 설정
  hoursBeforeStart: 2,  // N시간 전 자동 마감
}
```

#### 장기 근무 TO
```javascript
{
  jobType: "long_term",
  date: null,  // 사용 안함
  startDate: Timestamp(2025-03-01),
  endDate: Timestamp(2025-03-31),
  workDays: ["월", "수", "금"],  // 정기 근무 요일
  
  // 그룹 기능 불필요
  groupId: null,
  groupName: null,
  isGroupMaster: false,
  
  // 마감 설정
  applicationDeadline: Timestamp(2025-02-27 18:00),  // 고정 날짜+시간
}
```

### 생성 화면 차이

#### 단기 알바
- ✅ 캘린더 날짜 선택
- ✅ N시간 전 자동 마감
- ✅ 기존 공고 연결하기
- ✅ 그룹명 설정

#### 장기 근무
- ✅ 시작일/종료일 선택
- ✅ 근무요일 선택 (월,화,수,목,금,토,일)
- ✅ 특정 날짜+시간 마감 설정
  - 예: 2025-02-27 18:00
- ❌ 기존 공고 연결 (필요없음)
- ❌ 그룹명 (TO 1개뿐)

## 데이터 구조 설계

### 1. attendances 컬렉션 (근태 기록)

**선택한 방식**: A안 - 독립 컬렉션

**이유**:
- 지원자: 내 전체 근태 쉽게 조회 (단기+장기 통합)
- 관리자: 사업장별/TO별 근태 쉽게 조회
- 통합 통계: 한 컬렉션에서 집계 가능

#### 문서 구조
```javascript
attendances/{attendanceId}
{
  // 기본 정보
  uid: "user123",
  userName: "홍길동",
  
  // TO 정보
  toId: "to_001",
  businessId: "business_001",
  businessName: "○○물류센터",
  businessCategory: "물류센터",  // 통계용
  jobType: "short" / "long_term",  // 통계용
  
  // 근무 정보
  workDate: Timestamp(2025-03-15),
  workType: "피킹",
  
  // 약속된 시간 (기준)
  scheduledStart: Timestamp(18:00),
  scheduledEnd: Timestamp(22:00),
  
  // 실제 찍은 시간
  checkInRaw: Timestamp(17:50) or null,
  checkOutRaw: Timestamp(22:10) or null,
  
  // 승인된 시간 (급여 계산용)
  checkIn: Timestamp(18:00) or null,
  checkOut: Timestamp(22:00) or null,
  
  // 상태
  status: "AUTO_APPROVED" / "INCOMPLETE" / "EARLY_LEAVE" 
          / "EDIT_REQUESTED" / "MANUAL_APPROVED",
  
  // 잔업 여부
  hasOvertime: false,
  
  // 수정 요청
  editRequest: {
    checkIn: Timestamp(18:00),
    checkOut: Timestamp(22:00),
    reason: "일찍 도착했습니다",
    requestedAt: Timestamp,
  } or null,
  
  // 승인 정보
  approvedBy: "admin_uid" or "SYSTEM",
  approvedAt: Timestamp,
  
  // 급여
  wage: 53000,
  
  createdAt: Timestamp,
}
```

#### 쿼리 예시

**지원자: 내 전체 근태 조회**
```javascript
attendances
  .where('uid', '==', 'user123')
  .orderBy('workDate', 'desc')

// 결과: 단기+장기 모든 근무 기록
```

**관리자: 사업장별 근태 조회**
```javascript
attendances
  .where('businessId', '==', 'business_001')
  .where('workDate', '>=', '2025-03-01')

// 결과: 해당 사업장의 모든 근태
```

**통계: 카테고리별 집계**
```javascript
attendances
  .where('uid', '==', 'user123')
  .where('businessCategory', '==', '물류센터')

// 결과: 물류센터에서 일한 모든 기록
```

## 근태 관리 시스템

### 핵심 원칙

1. **기본 자동 처리** (Option 1 방식)
   - 출퇴근 찍으면 약속 시간으로 자동 세팅
   - 예외사항만 관리자 확인

2. **지원자 수정 요청 가능**
   - 잘못 찍은 경우 수정 요청
   - 관리자가 승인/거절

3. **관리자 최종 승인**
   - 특이사항 확인 후 승인
   - 급여 계산 기준

### 출퇴근 처리 로직

#### 1️⃣ 정상 케이스 (자동 처리)

**출근:**
```
지원자 출근 버튼 (17:50)
→ checkInRaw: 17:50
→ checkIn: 18:00 (자동 세팅)
→ status: AUTO_APPROVED
```

**퇴근:**
```
지원자 퇴근 버튼 (22:10)
→ checkOutRaw: 22:10
→ checkOut: 22:00 (자동 세팅)
→ status: AUTO_APPROVED
```

**결과:**
- 급여: 53,000원 (약속대로)
- 관리자 확인 불필요

#### 2️⃣ 예외 케이스 (관리자 확인 필요)

**Case 1: 출근만 찍음**
```javascript
{
  checkInRaw: Timestamp(18:00),
  checkIn: Timestamp(18:00),
  checkOutRaw: null,
  checkOut: null,
  status: "INCOMPLETE"
}
```
→ 관리자 확인 필요 알림

**Case 2: 퇴근만 찍음**
```javascript
{
  checkInRaw: null,
  checkIn: null,
  checkOutRaw: Timestamp(22:00),
  checkOut: Timestamp(22:00),
  status: "INCOMPLETE"
}
```
→ 관리자 확인 필요 알림

**Case 3: 조퇴 (약속보다 일찍 퇴근)**
```javascript
{
  scheduledEnd: Timestamp(22:00),
  checkOutRaw: Timestamp(19:00),
  checkOut: Timestamp(19:00),
  status: "EARLY_LEAVE"
}
```
→ 관리자 확인 필요 (급여 재계산)

**Case 4: 지원자 수정 요청**
```javascript
{
  checkInRaw: Timestamp(17:50),
  checkOutRaw: Timestamp(22:15),
  editRequest: {
    checkIn: Timestamp(18:00),
    checkOut: Timestamp(22:00),
    reason: "일찍 도착했습니다"
  },
  status: "EDIT_REQUESTED"
}
```
→ 관리자 승인 대기

**Case 5: 잔업 (약속보다 늦게 퇴근)**
```javascript
{
  scheduledEnd: Timestamp(22:00),
  checkOutRaw: Timestamp(23:00),
  checkOut: Timestamp(22:00), // 자동
  hasOvertime: true,
  status: "AUTO_APPROVED" // 일단 자동
}
```
→ 관리자 확인 필요 (잔업 승인 여부)
→ 승인 시: 22:30까지 인정 (30분 단위)

## 출퇴근 체크 방식

### 기술 비교

| 방식 | 장점 | 단점 | 비고 |
|------|------|------|------|
| **GPS** | 구현 간단, 별도 장비 불필요 | 실내 정확도 낮음, 50~100m 오차 | ✅ Phase 1 |
| **비콘** | 정확함 (1~5m), 실내 강력 | 사업장마다 설치 필요, 비용 발생 | Phase 2 |
| **Wi-Fi** | 기존 와이파이 활용 | 와이파이 없는 곳 불가, SSID 위조 가능 | 보류 |
| **QR코드** | 간단함 | 부정사용 가능성 높음 | ❌ 제외 |

### Phase별 구현 계획

**Phase 1 (MVP): GPS 기반**
- GPS 반경 + 시간대 체크
- 확정 상태에서만 활성화
- 당일만 출퇴근 가능

**Phase 2: 비콘 추가**
- 관리자 선택사항
- 원하는 사업장만 설치
- GPS와 복합 사용

**Phase 3: 정확도 개선**
- GPS + 비콘 조합
- AI 이상 패턴 감지

### GPS 출퇴근 활성화 조건

#### 출근 버튼 활성화
```javascript
if (
  application.status === "CONFIRMED" &&
  workDate === today &&
  isInGPSRange(businessLocation, 100m) &&
  currentTime >= scheduledStart - 1hour &&
  currentTime <= scheduledStart + 30min
) {
  // 출근 버튼 활성화
}
```

#### 퇴근 버튼 활성화
```javascript
if (
  attendance.status === "CHECKED_IN" &&
  isInGPSRange(businessLocation, 100m) &&
  currentTime >= scheduledEnd - 30min
) {
  // 퇴근 버튼 활성화
}
```

### 부정 방지 장치

1. **확정 상태 필수**
   - 아무나 출근 못 찍음
   - 관리자가 확정한 사람만

2. **당일만 가능**
   - 미리 찍기 불가
   - 지난 날짜 찍기 불가

3. **GPS 범위 체크**
   - 사업장 반경 100m 이내
   - 실시간 위치 확인

4. **시간대 제한**
   - 출근: 시작 1시간 전 ~ 30분 후
   - 퇴근: 종료 30분 전 ~ 이후

## 상태 흐름도

### 단기 알바 전체 상태 흐름

```
지원 (PENDING)
  ↓
  관리자 확정
  ↓
확정 (CONFIRMED)
  ↓
  당일 GPS 출근 버튼
  ↓
출근 (CHECKED_IN)
  ↓
  GPS 퇴근 버튼
  ↓
퇴근 (CHECKED_OUT)
  ↓
  관리자 근태 승인
  ↓
완료 (COMPLETED)
```

### 장기 근무 상태 흐름

```
지원 (PENDING)
  ↓
  관리자 확정
  ↓
확정 (CONFIRMED)
  ↓
  매 근무일마다 반복:
  │
  ├─ 당일 출근 → CHECKED_IN
  ├─ 당일 퇴근 → CHECKED_OUT
  └─ 관리자 승인 → COMPLETED
  
전체 근무 기간 종료
```

## 차별점 정리

### 기존 중개 앱
- 지원 → 확정 끝
- 실제 출근 여부 모름
- 급여 수동 계산
- 계약서 별도 작성

### 우리 앱 (AlFit)
- ✅ **지원 → 확정 → 출근 → 퇴근 → 급여**
- ✅ **실시간 근태 파악**
- ✅ **자동 급여 계산**
- ✅ **원툴 통합 관리**
- ✅ (추후) **전자계약서**

### 핵심 가치

1. **관리자 입장**
   - 실시간 출근 현황 파악
   - 자동 근태 관리
   - 급여 계산 자동화
   - 통합 관리 (지원~정산)

2. **지원자 입장**
   - 내 근무 이력 한눈에
   - 월별 급여 자동 집계
   - 출근율 통계
   - 신뢰도 프로필

3. **시스템 차별점**
   - 단기+장기 통합 관리
   - GPS 기반 출퇴근
   - 자동화된 근태 처리
   - 데이터 기반 신뢰 시스템
