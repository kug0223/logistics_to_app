## 왜 이 문서가 필요한가

이 Phase 는 세 경계를 **실제 Dart production 경로**로 닫는 것이 목표였다.
그중 두 개는 이 기기에서 실행할 수 없었다. 이유는 추측이 아니라 확인된
사실이다.

| 사실 | 확인 방법 |
|---|---|
| `ContractService` · `MonthlyReviewService` 는 `FirebaseFirestore.instance` 를 필드 초기화에서 잡는다 | 소스 (`contract_service.dart:20`) → Firebase 앱 없이 생성 불가 → `flutter test` 에서 실행 불가 |
| 이 기기의 Flutter 타깃은 Windows / Chrome / Edge 뿐 | `flutter devices` |
| Windows 데스크톱 빌드 불가 | `flutter doctor` → `Visual Studio not installed` |
| `firebase_app_check` 는 Windows 미지원 | pub 캐시에 `windows/` 없음 (core·auth·firestore·functions 는 있음) |
| 계약 서명 callable 두 개는 App Check 를 강제한다 | `functions/src/index.ts` — `enforceAppCheck: true` |
| 프로젝트에 web 타깃 없음 · DEV 에 web 앱 미등록 | `ls web` 없음 · `firebase apps:list` → ANDROID / IOS 뿐 |

즉 **제품의 실제 런타임은 Android** 이고, 그 빌드·설치는 사용자가 한다.
아래는 그 한 번의 실행으로 세 경계를 닫기 위한 최소 관찰 목록이다.

이 경계는 **DEV 런타임에서 이미 통과**했다(출근·퇴근 모두 근로자 본인 호출,
관리자 보정 0회). 기기에서는 화면이 그 사실을 맞게 말하는지만 본다.

DEV 실측 (2026-10-07, 15:00~15:10 근무):

| | 값 |
|---|---|
| 출근 | 14:37 입력 → `checkIn 15:00` (조출 반올림), `status present` |
| 조기 퇴근 시도 | 14:47 → 거절, `checkOut` 미생성, 근태 줄 1개 유지 |
| 정상 퇴근 | 15:11 입력 → `checkOut 15:10`, `originalCheckOut 15:11` |
| 근무시간 | `workHours 0.1667` (10분) |
| 관리자 개입 | `isModified false`, `modifiedBy` 없음 |

| # | 확인 | 결과 |
|---|---|---|
| C1 | 근무 종료 시각 **이전**에 퇴근을 누르면 `관리자에게 수동 수정을 요청하세요` 류의 안내가 뜨고, 출근 기록이 그대로 남는다 |  |
| C2 | 근무 종료 이후 퇴근을 누르면 성공한다 |  |
| C3 | 출근/퇴근 시각이 반올림됐다면 `출근 시간 HH:MM → HH:MM 으로 처리됐어요` 토스트가 뜬다 |  |

### D7 — 익명성 (중요)

리뷰 문서 ID 는 작성자를 역산할 수 없어야 한다. 앱이 만드는 ID 는
`biz_{사업장id}_{연}_{월}_{16자 해시}` 형식이다 (`generateKeyForBusiness`).

DEV 에는 지금 두 종류가 함께 있다:

| 문서 ID | 출처 |
|---|---|
| `biz_…_2026_10_2d4d25c80cae97ca` | canonical 형식 (이번 Phase) |
| `…_{근로자uid}_2026_10_U` | **직전 하네스 잔재** — 앱이 만든 것이 아니다 |

둘째 것 때문에 사업장 `reviewCount` 가 2 로 집계돼 있다. 기기에서 새로 제출한
리뷰의 ID 가 canonical 형식이면 이 항목은 닫힌다.

| # | 확인 | 결과 |
|---|---|---|
| D7 | 기기에서 제출한 사업장 리뷰의 문서 ID 가 `biz_…_16자해시` 형식이다 (Firestore 콘솔) |  |
