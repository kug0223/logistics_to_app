## P33-D / F4 — 처음부터 권한이 없는 진입 → **PATCH**

### 확인된 결손

`admin_contract_management_screen` 의 진입 게이트가 **거부·미확인·비소속을 한
덩어리로** `Navigator.pop()` 했다. 머무는 중 회수되는 경로에는 이미
`접근 권한이 없습니다` + `계약 관리 권한이 있는 관리자에게 문의하세요.` 가
있었으므로, **처음부터 없을 때만 말이 없었다.**

### 실재하는 권한 조정 경로 (소스 확인)

- `팀원 관리` = `user?.isBusinessAdmin == true` 게이트 → **서브관리자에게 메뉴가 없다.**
- 앱에 **"권한 요청" 기능은 없다**(전수 0건).
- 이 앱이 가진 canonical 안내 문구는 둘: 홈 Hero
  `필요하면 사업장 관리자에게 권한을 요청하세요.` / 계약
  `계약 관리 권한이 있는 관리자에게 문의하세요.`

→ **권한 요청 버튼·가짜 담당자 이름·권한 우회는 만들지 않았다.**
이미 이 화면이 쓰던 문구를 **그대로** 처음부터 거부에도 적용했을 뿐이다.

### 수정

진입 판정을 네 결과로 나눴다(`_EntryAccess`). **허용 조건은 한 글자도 바뀌지
않았다** — 갈라진 것은 거부의 이유뿐이다.

| 결과 | 무엇이 되는가 |
|---|---|
| `allowed` | 기존과 같다 |
| `denied`(이 사업장 서브관리자인데 계약 권한 없음) | **화면에 남아** `접근 권한이 없습니다` + 담당자 안내 |
| `unknown`(권한 조회 실패·멤버 문서 없음) | **`권한을 확인하지 못했습니다` + `권한이 없다는 뜻이 아닙니다.` + 다시 시도** — fail closed 는 유지 |
| `notMember`(비인증·일반 USER·이 사업장 비소속) | 기존대로 pop, 다만 `접근 권한이 없습니다.` 토스트 1회 |

`다시 시도`는 같은 진입 판정을 다시 돌릴 뿐 권한을 만들지 않는다.

### 증거

| 셀 | 확인한 것 |
|---|---|
| **ACX-1** | 처음부터 권한 없음 → 화면이 남고 이유·담당자가 보인다 |
| **ACX-2** | 그 상태에서 **계약 본문은 한 줄도 열리지 않는다**(검색창·목록 없음) |
| **ACX-3** | 권한 있으면 본문이 열린다(양성 대조) |
| **ACX-4** | 이 사업장과 관계없는 진입은 **여전히 닫힌다** |
| **ACX-5** | 320dp × 2.0 에서 거부 안내가 잘리지 않는다 |

**반례:** `denied` 를 pop 으로 되돌리면 **ACX-1·ACX-5 FAIL**, 복원 시 PASS.
ACX-3·ACX-4 는 되돌려도 PASS(양성 대조가 헛돌지 않는다).

**기존 재현 테스트 갱신:** P3-2 의 `WPD-1` 은 *"말없이 닫힌다"* 는 **옛 사실**을
고정하고 있었다. 지우지 않고 **새 정상 기대값으로 옮겼다**(같은 F4 owner).

**급여 제한은 이번에 건드리지 않았다.** 토스트 한 줄이 전부인 상태 그대로다 —
급여 경로는 화면을 열지 않고 `return` 하므로 "머물 화면"이 없고, 같은 수정이
성립하지 않는다. **F4 의 급여 쪽은 VERIFY 로 남는다.**

## P33-X1 / F7 — 제재 대상 식별 → **PATCH**

### 확인된 위험

상세 시트는 확인창을 띄우기 **전에** `Navigator.pop(ctx)` 으로 닫힌다.
그래서 시트에만 있던 `@아이디` 가 **정작 되돌리기 어려운 순간에는 사라져 있었다.**

| 행동 직전 화면 | 이전 원문 | 대상 식별 |
|---|---|---|
| 블랙리스트 해제 | `{이름}님의 블랙리스트를 해제하시겠습니까?` | **이름뿐** |
| 제재 해제 | `{이름}님의 제재를 해제하시겠습니까?\n현재: …` | **이름뿐** |
| 블랙리스트 등록(사유 입력) | 제목 `블랙리스트 등록` + 사유 힌트 | **대상 자체가 없다** |

이름이 같은 두 계정이면 세 문구가 **글자 하나 다르지 않았다.**

### 수정

`_targetLine(user)` 한 줄을 세 확인 지점에만 실었다 —
`{이름} · @{아이디} · {역할}( · {사업체명})`.

- **목록 행에는 아무것도 추가하지 않았다**(긴 식별자 강제 금지).
- **연락처·신분번호를 새로 노출하지 않았다** — 이미 상세에 있던 정보만 옮겼다.
- 쓰기 경계(`callableBlacklistUser`/`callableUnblacklistUser`/`callableResetPenalty`)와
  개별 계정 reader/권한 경계는 그대로다.

덤으로, 상세 시트의 통계 타일 그리드가 `childAspectRatio: 2.2` 고정이라
320dp × 2.0 에서 아래로 **70~104px 넘쳤다**. 조치 대상을 확인하는 자리라 수치를
지우지 않고, **글자가 커진 만큼 타일을 낮췄다**(`2.2 / textScale`, 1.0 하한) +
값·라벨 1줄 ellipsis.

### 증거

| 셀 | 확인한 것 |
|---|---|
| **ACX-6** | 상세에서 `@minsu01 · 지원자` 확인 → **시트가 닫힌 뒤에도** 확인창이 `@minsu01` 을 말한다 |
| **ACX-7** | 다른 동명이인을 고르면 사유 입력창의 식별자도 `@minsu77` 로 **바뀐다**(`@minsu01` 은 없다) |
| **ACX-8** | 320dp × 2.0 에서 확인창 식별자가 잘리지 않는다(그리드 overflow 포함 예외 0) |

**반례:** `_targetLine` 을 이름만 돌려주게 되돌리면 **ACX-6·7·8 FAIL** → 복원 PASS.
타일 비율만 2.2 로 되돌려도 **ACX-8 FAIL**.

**쓰기는 한 번도 실행하지 않았다** — 확인창을 여는 데까지만 갔다.
**오조치 사건은 지어내지 않았다.** 실제 사람이 도움 없이 대상을 알아보는지는
여전히 **USER OPEN**.

## P33-X2 / F6 — TO 한도의 단위·효력 → **PATCH(정적 설명만)**

### 화면과 source 의 차이

| 축 | source 에서 확정 | 이전 화면 |
|---|---|---|
| 세는 대상 | `status in [ACTIVE, FULL]` 인 공고 수 | `4개`·`7개` — **단위 없음** |
| 범위 | `ADMIN:{ownerUid}` — 그 계정의 **모든 사업장 합산** | 말하지 않음 |
| 적용 시점 | `callableCreateTO` **생성 시점**만, 기존 공고는 닫히지 않음 | 말하지 않음 |
| 현재 사용량 | 서버만 안다(`getEffectiveActivePostingCountTx`) | **reader 에 없음** |

그리고 관리자 카드 한 줄에 `2개 사업장 관리 중` 과 `개별 3개` 가 **나란히** 놓인다.
둘 다 `숫자 + 개` 라서 무엇의 수인지 문맥이 없었다.

### 수정 — 확정된 정적 설명만 더했다

두 탭에 같은 세 문장을 넣었다. 새 query·집계·인덱스는 **만들지 않았다.**

> 한도는 (한 관리자 계정이) 동시에 진행 중인 공고 수입니다 — 사업장 수가 아닙니다.
> 그 계정의 모든 사업장을 합쳐서 셉니다.
> 새 공고를 등록할 때만 적용되고, 이미 등록된 공고는 닫히지 않습니다.

관리자별 탭에서는 두 수가 나란히 있는 **목록 바로 앞**에 놓았다 — 배지를 길게
만들어 320dp 를 위협하지 않기 위해서다. 기존 문구
(`관리자별 개별 한도가 설정되지 않은 경우…`, `draft 상태로는 제한 없이 저장 가능합니다.`)는
그대로 남는다.

### 조회 실패 상태에서의 저장 (읽기만 확인)

P3-2 의 TOL-3 수정은 **되돌리지 않았다.** 전역값을 모르는 상태에서:

- 숫자를 말하지 않는다(`현재 기본 한도:` 없음, 대신 불러오지 못했다는 경고).
- 입력칸은 **비어 있다**.
- 그 상태로 `저장` 을 눌러도 `int.tryParse` 에서 막혀 **값이 만들어지지 않는다**.
- 버튼 자체는 살아 있다 — **사용자가 명시적으로 새 값을 넣어 저장하는 것은
  정당한 행동**이고, 막아야 할 것은 가짜 기본값의 자동 저장이었다. 그건 없다.

### 증거

| 셀 | 확인한 것 |
|---|---|
| **ACX-9** | 전역 탭이 단위·합산 범위·적용 시점을 말한다 + 기존 draft 문구 유지 |
| **ACX-10** | 관리자별 탭도 같은 말을 하고, `2개 사업장 관리 중`·`개별 3개`·`전역 7개` 가 함께 보인다 |
| **ACX-11** | 전역값 UNKNOWN 상태에서 저장을 눌러도 입력칸이 여전히 비어 있다(가짜 4 없음) |
| **ACX-12** | 320dp × 2.0 에서 단위 설명이 예외 없이 그려진다 |

**반례:** 세 문장을 지우면 **ACX-9·10·12 FAIL** → 복원 PASS. ACX-11 은 되돌려도 PASS.

**사람이 `N개 사업장` 을 여유로 읽는지는 관측하지 않았다** — 오해를 확정하지
않았고, 사용량 표시를 만들지도 않았다. **F6 의 "꼭 보여줘야 하는가"는 USER OPEN.**
