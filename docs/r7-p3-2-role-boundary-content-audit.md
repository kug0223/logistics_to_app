## P32-H — 제안/수락 조건 (같은 사건 키)

### 같은 키를 두 화면에 먹였다

`businessId biz1 · toId to1 · slotId slot1 · wdId wd1 · 2026-09-29 · 홀서빙 09:00~18:00`
— 비슷한 제목의 다른 fixture 를 나란히 둔 것이 아니라 **한 벌의 상수**를
관리자 경계(`DayApplicantsReads`)와 지원자 경계(`MyApplicationsReads`)에 그대로 넣었다.

| 측 | 렌더된 실제 문구 | 증거 |
|---|---|---|
| 관리자 결과 | `초대 수락 · 확정` / `초대 거절` / `초대 철회` (`최근 초대 응답` 묶음) | **IHK-1** |
| 지원자 수신 | `근무 초대` · `근무 초대가 도착했어요` · `9월 29일 (화) · 09:00~18:00` | **IHK-2** |
| 지원자 행동 | `수락하기` + `거절` — 탭해도 **확정이 선언되지 않는다** | **IHK-2** |
| 지원자 UNKNOWN | `근무 가능 여부를 확인하지 못했어요` · `새로고침 후 다시 확인해 주세요` · **수락 CTA 없음**, `거절`만 | **IHK-2b** |
| 거절의 주체 | `초대를 거절했어요`(내가) ↔ `이번 지원은 확정되지 않았어요`(관리자가) | **IHK-3** |
| 수락 뒤 남은 것 | `9월 29일 출근 예정이에요` | **IHK-4** |

### 판정

- **발송과 확정이 구별된다.** 관리자 쪽은 초대가 어떻게 끝났는지 세 갈래로 남고,
  확정 명단에 섞여 사라지지 않는다(`invitedAt` 으로 provenance 유지).
- **수락 조건과 남은 단계가 구별된다.** 수락은 확정 선언이 아니고, 확정된 건은
  `출근 예정`이라는 **다음 약속**으로 이어진다.
- **UNKNOWN 을 가능으로 바꾸지 않는다.** 자리 상태를 서버가 확인해 준 경우에만
  수락 CTA 가 뜬다(`canAcceptInvite == available`). 거절은 자리와 무관하므로 남는다.
- **NO_PERMISSION ≠ ERROR.** `canManageTo` 가 없으면 초대 영역을 아예 조회하지 않고
  빈 목록으로 둔다 — `확인하지 못했어요`(ERROR)로 표시하지 않는다.

### 격리에서 못 본 것 (CODE only)

수락 **확인창**(`이 업무에 참여하시겠습니까? / 수락 후 일정 충돌이 없으면 확정됩니다. /
동의하고 초대 수락`)은 렌더하지 못했다. `_acceptInvite` 가 확인창 전에
`TaxIdentityService.loadStatus()` → `meetsApplyPrerequisites(...)` 라는 **서류 문턱**을
지나며, 격리 표본이 그 문턱을 넘지 못했다. **테스트용 자격 우회를 넣지 않았다.**
→ 그 자체가 사실이다: **수락도 직접 지원과 같은 문턱을 지난다.**

실제 **발송·수락·확정 writer 와 FCM 전달은 실행하지 않았다**(공유 DEV READ ONLY).

### 이 셀 밖에서 관찰된 것 — 기존 owner 로 넘김

320dp × 배율 2.0 에서 **확정 명단 행**(`ApplicantRowSurface`)에 RenderFlex overflow
**3건**(62px · 14px 등)이 난다. 초대 결과 세 갈래 문구 자체는 같은 조건에서 그대로
읽힌다(**IHK-5**). 이 셀이 묻는 정보가 아니고, 같은 Row 는 이미
`R7-P1-2 DEVICE.1H.1` 이 손댄 적이 있는 영역이므로 **여기서 고치지 않는다.**
IHK-5 가 그 overflow 를 **사실대로 확인**하므로, 그 줄이 실패하면 overflow 가
사라졌다는 신호다. → **P1-2 DEVICE owner**.

## P32-D — 급여 권한 거부 후에 남는 것

### P3-1 의 F4 서술을 정정한다

P3-1 에서 *"계약 관리에는 담당자 안내가 있고 급여에는 없다"* 고 적었다.
**그 대조는 절반만 맞다.** 실제로 렌더해 보니 계약 화면의 안내는
**머무는 중 권한이 회수된 경우에만** 나온다.

| 상황 | 계약 관리 | 급여 |
|---|---|---|
| **처음부터 권한 없음** | 화면이 **열리지 않고 그냥 닫힌다** — 토스트도 이유도 담당자도 없다(`_canAccessTargetBusiness()` → `Navigator.pop()`) | 토스트 `급여 관리 권한이 없습니다.` + `return` — 화면 전환 없음 |
| **머무는 중 회수** | `접근 권한이 없습니다` + **`계약 관리 권한이 있는 관리자에게 문의하세요.`** | (해당 경로 없음) |

증거: **WPD-1**(처음부터 없음 → 이전 화면으로 되돌아오고 두 문구 모두 없음) ·
**WPD-2**(권한 있으면 열린다, 양성 대조) · **WPD-3**(회수 → 이유+담당자) ·
**WPD-4**(320dp × 2.0 에서 두 문구 안 잘림).

### 권한을 조정할 실제 경로가 있는가

- `팀원 관리`는 `user?.isBusinessAdmin == true` 게이트다 → **서브관리자에게는 메뉴가 없다**
  (권한 부여 = 이양이라는 설계 의도. 거짓 완료도 데이터 노출도 아니다).
- 앱에 **"권한 요청" 기능은 없다.** 소스 전수에서 요청 행동은 0건이다.
- 이 앱이 가진 canonical 안내 문구는 두 개뿐이다:
  홈 Hero `필요하면 사업장 관리자에게 권한을 요청하세요.` ·
  계약 회수 `계약 관리 권한이 있는 관리자에게 문의하세요.`

### 결론

막힌 서브관리자가 **다음에 무엇을 해야 하는지**는, 급여에서도 계약 진입에서도
화면이 말하지 않는다. 앱에는 이미 같은 뜻의 문구가 두 개 있으므로 **말할 수는 있다.**

다만 이것은 **거짓 주장도 오도도 아니라 부재**이고, 사람이 실제로 막혀서 헤매는지는
**관측한 적이 없다.** 그래서 **문구를 이번에 추가하지 않는다** — F4 는 **VERIFY** 유지.
권한 우회나 제한 업무 노출로 해결하지 않는다.
발견성·불편은 **HEURISTIC**이다.

**NO PATCH** — 정확한 상태: 급여는 토스트만(담당자 안내 없음), 계약 진입 거부는
**무안내 pop**, 회수 시에만 안내. 미관찰: 실제 사람의 막힘.

## P32-X1 — 문의 대상 식별 (내용 렌더)

표본: **이름이 같은 세 계정** — `김민수/@minsu01`(지원자) · `김민수/@minsu77`(지원자) ·
`김민수/@bizminsu`(관리자, `businessName` 있음). 연락처는 없는 계정으로 둔다.

| 관찰 | 증거 |
|---|---|
| 목록 카드는 **이름 · 역할 배지 · (있으면)연락처 · 근무일수**만 보인다. **`@아이디` 가 목록에 없다** | **SAU-1** |
| 지원자 두 명은 역할 배지까지 같아 **목록에서 구별되지 않는다** | SAU-1 |
| 카드를 **탭해야** 상세 시트에서 `@minsu01 · 지원자` 가 나온다 | **SAU-2**(실제 탭) |
| 지원자 상세에는 `사업체명` 행이 **없다** | SAU-2 |
| 관리자 상세에는 `@bizminsu · 사업장관리자` + `사업체명` + `강남 물류센터` 가 붙는다 | **SAU-2b**(양성 대조) |
| 320dp × 2.0 에서 이름 3개가 예외 없이 그려진다 | SAU-5 |

### 문의 유형상 필요한 문맥인가

- **동명이인 구별**은 가능하다. 다만 수단이 **목록이 아니라 상세**에 있고,
  나머지 수단은 `effectivePhone`(있을 때만, 개인 연락처)과 아이디 검색(문의자가
  아이디를 알려줘야 함)이다. **개인 연락처 노출을 해결책으로 삼지 않는다.**
- **사업장 범위**는 지원자에게 `businessName` 이 **원천에 없다**. 사업장 소속 문의라면
  결손이고, 계정 자체 문의(블랙리스트·제재 해제)라면 필요 없는 문맥이다.
  가능한 조치가 `블랙리스트 해제`·`제재 해제` 두 가지뿐이므로 **현재 조치 범위에는
  치명적이지 않다.** → **F7 VERIFY 유지**, 새 집계·조회를 발명하지 않는다.

### 확정 결함 1 — 조회 실패를 "대상 없음"으로 말했다

`_loadAllUsers` 가 실패하면 토스트 한 줄이 뜨고 사라진 뒤 화면에는
**`해당하는 사용자가 없습니다`** 만 남았다. 문의 대상이 정말 없는 것과 못 읽은 것은
다른 사실이다.

- 수정: `_loadError` 분기 — `사용자 목록을 불러오지 못했습니다` +
  `해당하는 사용자가 없다는 뜻이 아닙니다.` + `다시 시도`.
- 전후 대조: 분기를 되돌리면 **SAU-3 FAIL** → 복원 PASS.
  정말 빈 경우의 **SAU-4 는 되돌려도 계속 PASS**(양성 대조가 헛돌지 않는다).
- 읽기 경계 신설: `all_users_reads.dart`(`allUsersRaw` 1개). **쓰기는 넣지 않았다** —
  블랙리스트·제재 해제는 경계 밖에 그대로 둔다.

## P32-X2 — TO 한도의 의미 (내용 렌더)

표본: 전역 **7**, 관리자 둘 — 사업장 **2개**·개별 한도 **3**, 사업장 **1개**·개별 없음.
사업장 수와 한도를 **일부러 다른 수**로 두었다.

| 화면이 말하는 것 | 증거 |
|---|---|
| `현재 기본 한도: 7개` | **TOL-1** |
| `관리자별 개별 한도가 설정되지 않은 경우 이 값이 적용됩니다.` | TOL-1 |
| `draft 상태로는 제한 없이 저장 가능합니다.` (예외를 말한다) | TOL-1 |
| `2개 사업장 관리 중` 옆에 `개별 3개` — **다른 수로 나란히** 뜬다 | **TOL-2** |
| 사업장이 1개면 그 줄 자체가 없고(`managedBizCount > 1` 조건) `전역 7개` 만 | TOL-2 |
| 320dp × 2.0 에서 한도 수치와 `저장` 이 예외 없이 그려진다 | TOL-6 |

### 실제 강제 규칙과의 대조

| 축 | 서버(CF) | 화면 |
|---|---|---|
| 세는 단위 | `status in [ACTIVE, FULL]` 인 **유효 활성 공고 수** | `4개`·`7개` — **단위를 말하지 않는다** |
| 범위 | `ADMIN:{ownerUid}` — **오너의 모든 사업장 합산** | `관리자별 한도` 라고만 한다(사업장당이라고 **말하지는 않는다**) |
| 적용 시점 | `callableCreateTO` **생성 시점**만 | **말하지 않는다** — 기존 공고가 닫히는지 알 수 없다 |
| 대상의 현재 사용량 | `getEffectiveActivePostingCountTx` 로 서버만 안다 | **reader 에 없다**. 행에 뜨는 수는 **사업장 수**다 |

`N개 사업장 관리 중` 이 사용량으로 읽힐 여지는 있으나 **오해를 미리 확정하지 않는다** —
TOL-2 가 두 수를 **다르게** 보여 혼동 가능성을 재현했을 뿐, 사람의 오독은 관측이 없다.

**꼭 보여줘야 하는가 / 지금 자료로 가능한가는 별개다.** 단위·적용 시점은 현재 자료만으로
말할 수 있지만(정적 사실), **남은 여유**는 reader 에 없는 값이다.
→ **새 집계·인덱스를 이 UI patch 로 발명하지 않는다.** F6 **VERIFY** 유지, owner VJ13.

### 확정 결함 2 — 못 읽은 값을 확정 숫자로 말했다

전역 탭 조회가 실패하면 `현재 기본 한도: 4개` 가 **그대로 남고** 입력칸에 `4` 가
미리 채워졌다. 그 상태로 `저장` 하면 **실제 설정을 4로 덮어쓴다.**

- 수정: `_globalLoadFailed` — `현재 기본 한도를 불러오지 못했습니다.` +
  **`지금 값을 저장하면 실제 설정을 덮어씁니다.`** + `다시 시도`, 입력칸 **프리필 제거**.
- 전후 대조: 되돌리면 **TOL-3 FAIL** → 복원 PASS.

### 확정 결함 3 — 조회 실패를 "관리자 없음"으로 말했다

`_loadAdmins` 실패 시 `등록된 사업장 관리자가 없습니다` 가 떴다.

- 수정: `_adminsLoadFailed` — `관리자 목록을 불러오지 못했습니다` +
  `등록된 관리자가 없다는 뜻이 아닙니다.` + `다시 시도`.
- 전후 대조: 되돌리면 **TOL-4 FAIL** → 복원 PASS.
  정말 빈 경우의 **TOL-5 는 되돌려도 계속 PASS**.
- 읽기 경계 신설: `to_limit_reads.dart`(`globalConfigRaw` · `businessAdminsRaw`).
  **저장(`maxActiveTOPerBusiness` 쓰기 · `callableSetAdminTOLimit`)은 넣지 않았다.**

**설정 저장·기존 공고 자동 마감·실제 생성 차단은 하나도 실행하지 않았다.**
